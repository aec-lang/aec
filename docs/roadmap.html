وضعیت واقعی، بدون تیک تزئینی

نسخهٔ قبلی این صفحه همه‌چیز را ۱۰۰٪ می‌نمود. آن ادعا درست نبود: امضای GPG هرگز اجرا نشد و sandbox مک/ویندوز روی میزبان خودشان آزموده نشد. وضعیت صادقانه:

  1. ✓ نوع nominal: struct/enum با constructor، alias، namespace، equality و pattern matching پیاده و تست شده‌اند.
  2. ✓ سه سیستم‌عامل: workflow روی Linux، macOS و Windows (build، test، clippy، package، smoke) روی tag v0.1.0 موفق شد.
  3. ✓ سندباکس لینوکس: bubblewrap واقعاً اجرا شد؛ خواندن بیرون از workspace و نوشتن داخل آن هر دو fail-closed شدند (scripts/sandbox-selftest.sh).
  4. ○ سندباکس macOS و Windows: کد نوشته و از نظر نحوی بررسی شد، ولی روی میزبان آن سیستم‌عامل‌ها اجرا نشده. اسکریپت Windows هم از Start-Job (که اصلاً مرز امنیتی نیست) به Windows Sandbox واقعی تغییر کرد.
  5. ✓ امضای release: scripts/sign-release.sh با یک کلید موقت ساخته و gpg --verify روی خروجی موفق شد. کلید واقعی انتشار باید در CI به‌صورت secret تنظیم شود.
  6. ✓ دانلودپذیری: scripts/install-release.sh باینری‌های release را با تأیید SHA256SUMS نصب می‌کند. تا وقتی tag v* push نشود، لینک دانلود کار نمی‌کند.

APM: apm init، add، remove، install، list، tree با apm.toml/apm.lock، به‌همراه registry محلی امضاشده با Ed25519. راهنما: APM.

✗

مرزهای باز — چیزهایی که ۱۰۰٪ نیستند

  • registry خارجی: APM فقط پوشهٔ محلی است. کلاینت HTTP، چرخش کلید و اتصال verification به import رانتایم وجود ندارد.
  • سندباکس مک/ویندوز: کد نوشته شده ولی روی میزبان خودشان اجرا نشده؛ sandbox-selftest.sh برای این دو untested گزارش می‌دهد. بدون این دو، پوشش سه‌سکویی sandbox کامل نیست.
  • QA بصری روی مک/ویندوز: تست‌ها headless و روی هر سه سیستم‌عامل سبزند، اما بازبینی چشمی پنجرهٔ native روی مک و ویندوز انجام نشده.
  • معماری: بدون generic inference، runtime ناهمگام، پروتکل A2A و IDE.

بسته‌شده در این جلسه (۲۰۲۶-۱۰-۰۲): انتشار واقعی — release v0.1.0 با سه آرشیو Linux/macOS/Windows، SHA256SUMS و امضای GPG منتشر شد و install-release.sh از همان آرشیوها نصب می‌کند؛ و CI سه‌سکویی که سه شکست واقعی داشت (مسیر sandbox، termios ویندوز، و symlink سیستمی مک/ویندوز) و هر سه رفع شد.

جلسهٔ ۴: «زبان» از نظر فیچر بسته شد. شش آیتم تمام شد — var تغییرپذیر، Interpolation رشته، Result/?، Lambda/Closure، گیت نوع در aec run، و Quick Wins. ضمن کار سه باگ از قبل موجود هم پیدا و رفع شد (پایین‌تر توضیح داده شده‌اند).
اکنون import چندفایلی، pub، alias عمومی و namespace چندلایه در CLI اجرا می‌شود؛ component/theme/model/type alias، package workspace و smoke native نیز تست شده‌اند. برای ۱۰۰٪ فقط QA بصری، registry/signing و sandbox سیستم‌عامل باقی است.
🐞
سه باگ پنهان که سر راه پیدا شد — هر سه از یک جنس: قابلیتی که در گرامر «بود» ولی عملاً کار نمی‌کرد.
  • none به‌عنوان مقدار هرگز پارس نمی‌شد (let x = none می‌ترکید).
  • ? در نوع بی‌صدا دور ریخته می‌شد؛ int? همان int می‌شد.
  • لیست builtinهای چکر ناقص بود → هشدار کاذب «متغیر تعریف‌نشده» برای upper، min، ls و…
ریشهٔ مشترک دو مورد اول: یک literal بی‌نام داخل قاعدهٔ silent پارس را موفق می‌کند ولی به سازندهٔ AST هیچ چیزی نمی‌رساند. هر سه با تست نگهبان قفل شدند.

جمع‌بندی یک‌خطی: AEC یک زبان کاربردی با هستهٔ runtime، type checker، UI واکنشی، حافظه، مجوز داخلی، مدل‌های LLM، ماژول‌های عمومی و APM امضاشده است — ۳۷۳ تست سبز، CI سه‌سکویی موفق (شامل clippy) و release منتشرشدهٔ v0.1.0 با امضای GPG. آنچه واقعاً باز است: registry شبکه‌ای APM، سندباکس تأییدنشدهٔ مک/ویندوز و بازبینی چشمی پنجرهٔ native روی مک/ویندوز.
⚠️
محدودیت‌هایی که باید بدانی (جزئیات در بخش ۶ و ۹ هندآف):
  • shell.run، environment و memory پایدار با بلاک مجوز رد می‌شوند، مدل به allowlist شبکه می‌رود و redirect دنبال نمی‌شود. این محافظ sandbox سیستم‌عامل نیست.
  • map/filter/reduce با closure کار می‌کنند؛ برای lambda چندپارامتری در آرگومان، پرانتز را در syntax رعایت کن.
  • capture در lambda by-move است (snapshot در لحظهٔ ساخت)، نه by-reference.
  • سندباکس مک/ویندوز روی میزبان خودشان آزموده نشده؛ ادعای «سه‌سکویی تأییدشده» فقط برای لینوکس درست است.
